# 图片原图与派生图存储策略

本文记录第六章第 4～5 步的字段语义、原图保留策略和派生图生成规则。第 4 步建立数据契约、迁移和清理边界；第 5 步已经接入 COS 数据万象，在上传时生成主展示 WebP 和缩略 WebP。

## 字段语义

| 字段 | 可空 | 对外返回 | 语义 |
| --- | --- | --- | --- |
| `originalUrl` | 否 | 仅管理员原始实体接口 | 当前图库 COS 中的原始上传文件。用于重新生成派生图、排障和未来的原图下载。上传或替换成功后立即写入，普通编辑不能修改。 |
| `url` | 否 | 是 | 主展示图地址。生成的 WebP 比原图更小时使用 WebP，否则回退 `originalUrl`。详情页及不支持缩略图的客户端继续使用该字段。 |
| `thumbnailUrl` | 是 | 是 | 列表缩略 WebP 地址。原图不超过 20 KB、GIF、生成失败或缩略图不比展示图小时为 `NULL`；客户端必须使用 `thumbnailUrl ?? url` 回退。 |
| `sourceUrl` | 是 | 否 | URL 导入时的外部来源地址，仅用于追踪来源，不代表本项目管理的 COS 文件，也不参与文件删除。 |

`picSize`、`picWidth`、`picHeight`、`picScale`、`picFormat` 继续描述 `originalUrl` 对应的原始文件，不复用这些字段描述派生图，避免语义混乱。

## 历史数据与兼容

执行 `sql/alter_picture_derivative_urls.sql` 后：

```text
originalUrl = 原有 url
url         = 原有 url
thumbnailUrl = NULL
```

因此迁移后页面展示没有变化。第 6 步前端已接入缩略图，保留缺失或空白 `thumbnailUrl` 时使用 `url` 的历史数据回退。

迁移脚本只执行一次；现有数据库不要重新执行完整的 `create_sql.sql`。

## 新上传与替换

新上传采用：

```text
上传原图到 COS
  → 非 GIF 尝试生成主展示 WebP
  → 大于 20 KB 的非 GIF 尝试生成 512 x 512 边界内的缩略 WebP
  → originalUrl = 原图 URL
  → url = 更小的主展示 WebP；否则回退原图 URL
  → thumbnailUrl = 比展示图更小的缩略 WebP；否则为 NULL
```

替换图片时，数据库事务提交三个新地址（未生成缩略图时清空旧字段）后，再尽力清理旧记录关联的三个文件。首次删除同步执行，失败后定时重试；不是全部异步清理。三个地址先去重，避免兼容阶段 `url == originalUrl` 时重复删除。

生成成功时会得到三个用途明确的对象：

```text
originalUrl  原始格式，长期保留
url          主展示 WebP
thumbnailUrl 列表缩略 WebP
```

COS 返回结果按对象 Key 匹配，不依赖返回列表顺序；地址使用预定规范 Key 构造，避免返回 Key 的前导斜杠影响地址。数据库事务失败时会去重清理本次原图、展示图和缩略图。原图元信息有效但派生结果缺失时回退；体积收益不足时尝试删除无收益对象。COS 请求抛出异常或原图元信息无效时上传失败，并尝试清理预定 Key，不声称所有云端故障都能回退成功。

GIF 暂不生成派生 WebP。在确认腾讯云处理能够稳定保留动画帧之前，`url` 继续使用原始 GIF，避免上传后动图变成静态图片。

## 删除和草稿清理

删除图片、替换图片和过期草稿清理必须处理当前图库管理的全部对象：

```text
originalUrl
url
thumbnailUrl
```

相同 URL 只删除一次。`sourceUrl` 是站外来源，不允许交给 COS 删除逻辑。

数据库记录删除或更新先完成，COS 删除失败进入现有有限重试队列，不回滚已经完成的数据库事务。

边界：上述业务清理队列仅保存在进程内，重启会丢失，不能称为持久可靠投递。`FileManager` 内的上传失败/无收益对象清理目前只有尽力删除与错误日志，没有接入该队列；缺失的派生结果也不能据此证明云端对象未产生。生产环境仍需持久清理任务或定期对账兜底，不把补偿尝试等同于绝对一致性。

## 缓存和接口约束

- `thumbnailUrl` 进入 `PictureVO`，公开列表缓存可随图片记录一起保存；`originalUrl` 不进入公开 VO。
- 管理员不脱敏的 `Picture` 接口能够看到 `originalUrl`，便于运维排查。
- 每次上传、替换和派生图地址切换都在同一图片写事务中推进公开列表版本号，避免公开列表继续选择旧版本缓存。

## 前端接入与真实环境验收

1. 在真实 MySQL 执行 `alter_picture_derivative_urls.sql` 并核对历史行的 `originalUrl`。
2. 使用真实 COS 分别上传 JPG、PNG、WebP、GIF 和小于 20 KB 的图片，核对输出对象与体积选择。
3. 前端列表已接入缩略图优先、主图回退和原生懒加载，缩略图 404 时也尝试主图；详情继续使用 `url`，管理员点击后才加载主图预览。真实后端联调仍待完成。
4. 根据真实图片和页面尺寸调整 `picture.derivative` 下的质量、缩略尺寸和阈值配置。
